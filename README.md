# DeepWiki 转 Markdown ｜ 架构笔记导出

一个 Chrome 扩展（Manifest V3），把 **DeepWiki** 的内容一键导出成干净的 Markdown 文件，用来整理架构学习笔记。

- **Wiki 页面** → 带标题层级、表格、列表、代码块、Mermaid 架构图的 Markdown
- **问答页面**（`/search/...`）→ 问题 + 回答的 Markdown，可整页合集、也可逐条导出
- **一篇一个文件夹**：`<下载目录>/DeepWiki/<owner>/<repo>/<页面>/index.md` + `assets/`，一篇内容自成一体，随时整包搬走
- **支持翻译后的页面**：直接从实时 DOM 提取，沉浸式翻译、陪读蛙（read-frog）等写回页面的译文会被原样导出
- **引用标记自动变成 GitHub 源码链接**：`milvus.yaml:17-18` → 可点击跳到 GitHub 对应行
- **笔记夹**：把不同问答页面的内容收集起来，最后汇总成一份笔记
- **整站批量导出（自动翻页）**：在当前标签页里逐页打开、抓完即存，一次导出某个仓库的全部 Wiki 页面（每页一个文件夹）+ 仓库级 `00-目录.md`；默认只导出原文（快），译文可留待大模型统一处理
- **重复导出即覆盖更新**：同名 `.md` / `.svg` 直接覆盖，不会产生 `xxx (1).md` 副本

---

## 一、安装（3 步）

1. 打开 Chrome，地址栏输入 `chrome://extensions/`
2. 打开右上角的 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本文件夹 `deepwiki-md-exporter`

装好后打开 `https://deepwiki.com/` 任意页面，右下角会出现一个紫色的 **MD** 悬浮按钮。

> 首次安装后，已经打开的 DeepWiki 页面需要刷新一次，扩展才会注入。

## 二、怎么用

### 1. 导出某个 Wiki 页面

打开例如 `https://deepwiki.com/milvus-io/milvus/1-overview`：

- **方式 A**：点右下角悬浮的 **MD** 按钮 → *下载 Markdown*
- **方式 B**：点浏览器工具栏的扩展图标 → *下载 Markdown*

导出内容包含：页面全部正文（标题层级、段落、列表、表格、代码块）、Mermaid 架构图、以及所有指向 GitHub 源码的引用链接。

### 2. 导出问答（重点）

打开例如 `https://deepwiki.com/search/etcd_2338b55c-...`：

- **整页导出**（默认）：把页面上所有问答按顺序合成一个文件，每条问答是一个 `## Q1. 问题…` 小节，结尾附该问答的来源文件清单
- **逐条导出**：在面板/弹窗的「本页问答」列表里，每条问答右侧有三个按钮
  - `MD` 下载这一条
  - `复制` 复制这一条到剪贴板
  - `＋` 加入笔记夹

### 3. 笔记夹（把多页问答合并成一份笔记）

在看问答页时，点 **＋ 加入笔记夹**，内容会暂存在扩展本地。收集够了以后：

- 面板底部 / 弹窗「笔记夹」区块 → **导出** 或 **复制**
- 会按仓库分组、按收集时间排序，输出一份完整的 `DeepWiki-问答笔记-日期.md`
- 扩展图标上的角标数字 = 当前收集的条数

### 4. 整站批量导出（自动翻页）

在任意 Wiki 页面（不是问答页）的面板/弹窗里点 **批量导出整个 Wiki**：

- **在当前标签页里自动翻页**：顺着左侧目录逐页打开（单页应用内跳转，不整页刷新）
- 每页等「正文 + Mermaid 架构图」渲染完整后提取，每页导出为一个独立文件夹
- 仓库根目录下同时生成 `00-目录.md`，里面是全部页面的本地链接，可直接作为笔记库的入口
- 页面右下角显示进度，**随时可以点「停止」**；全部跑完后会自动回到你开始导出时的那一页
- 重复导出同名页面会**直接覆盖**旧文件，不会产生 `index (1).md` 这种副本

**译文处理**由设置项「批量导出的译文处理」决定（默认：只导出原文）：

| 模式 | 行为 | 适合 |
| --- | --- | --- |
| **只导出原文（默认）** | 页面**根本不滚动**，翻译插件的懒翻译不会被触发；速度最快、内容完整 | 导出后交给大模型统一翻译 |
| 逐页等待译文 | 每页滚动多轮、等译文补齐再抓取，直接得到中文 | 想马上拿到中文笔记 |

> 原文模式下如果检测到陪读蛙，「页面翻译」开关是开着的，扩展会先把它**临时关掉**
> （否则正文会被就地替换成中文、原文就没了），整趟导出结束后再自动恢复原状态。
>
> 速度参考：84 页的仓库（milvus）逐页等待译文约 39 分钟；
> 原文模式因为不滚动、不等翻译，每页只需等正文和图表渲染，快一个数量级。

### 5. 单页导出：使用翻译插件时

单页导出（面板的「下载 Markdown」）导出的是**页面上当前显示的内容**，所以：

1. 先用翻译插件翻译页面，等翻译完成
2. 再点导出

关于**陪读蛙（read-frog）**这类「按视口懒翻译」的插件：

- 它只翻译你**滚动到过**的部分（预加载边距约一屏）。所以长文章如果只看了开头就导出，
  后面大半还是英文。本扩展在导出前会估算译文覆盖率，低于 85% 时会问你要不要
  **自动滚动整页、等翻译补齐再导出**——选「确定」即可。
- 单页导出时扩展会尽力帮你打开陪读蛙的页面翻译开关。
  这是**开关**，扩展会核对状态、点错时自动纠正（详见「关键实现说明」）。
- 它有两种译文形态，本扩展都能识别与统计：
  **双语对照**（另插一个译文节点）和**仅译文**（原文本地替换）。

其他行为：

- 插件把译文写进页面 DOM → 译文会被导出，并且**译文会单独成段**，不会和英文原文粘成一行
- 扩展会丢弃「加载中／报错」这类插件的界面节点；但对于正在淡入（半透明）的译文节点会保留，
  不会被当成隐藏元素删掉
- 「仅译文」模式下原文本地替换，导出即纯中文
- 想要中英对照笔记，就用「双语对照」模式导出，两种语言都会保留
- 代码块、文件名、GitHub 链接不会被翻译插件改写（它们本来就不参与翻译），导出后仍然可用

### 6. 设置项

点扩展图标 → 「设置」：

| 设置 | 说明 |
| --- | --- |
| 输出 front-matter | 文件开头加 YAML 元信息（标题、仓库、来源、导出时间） |
| 正文顶部显示来源 | 在正文最前面插入一行「仓库 / 来源 / 页面」 |
| Wiki 保留「相关源文件」 | 是否保留 DeepWiki 页首那个 *Relevant source files* 折叠列表（默认关闭，避免文件列表过长） |
| 问答保留「来源文件」 | 每条问答结尾列出引用的源文件（默认开启） |
| 引用标记转 GitHub 链接 | 把 `milvus.yaml:17-18` 变成可点击的 GitHub 链接（默认开启） |
| 忽略页面隐藏元素 | 丢弃 `display:none` 等不可见元素，配合翻译插件使用（默认开启） |
| 回答标题降一级 | 问答导出时把回答里的 `##` 降为 `###`，让问题标题独占一级（默认开启） |
| 图表 | `独立 .svg 文件`（默认，兼容 Obsidian / Typora / VS Code）／`内嵌 base64`（单文件自包含，体积大）／`忽略` |
| 批量导出的译文处理 | `只导出原文`（默认，快）／`逐页等待译文`（慢，直接出中文）／`每次导出前询问` |
| 一篇一个文件夹 | 默认开启。`DeepWiki/<owner>/<repo>/<页面>/index.md + assets/`，关掉则退回平铺模式 |
| 下载根目录 | 默认 `DeepWiki`，即下载目录下的第一层文件夹 |
| 文件夹内正文文件名 | 默认 `index`，最终文件名是 `<这个值>.md` |
| 文件名模板 | 平铺模式下的命名规则，见下方变量 |

文件名模板可用变量：`{repo}` `{pageId}` `{title}` `{date}` `{time}` `{type}` `{count}`

## 四、下载目录结构

默认开启「一篇一个文件夹」，一个仓库就是一整棵干净的树：

```
下载/
└── DeepWiki/
    └── milvus-io/
        └── milvus/
            ├── 00-目录.md                        ← 批量导出时生成，入口
            ├── 1-overview/
            │   ├── index.md                      ← 正文，图片引用 assets/xxx.svg
            │   └── assets/
            │       ├── 1-overview-diagram-1.svg
            │       └── 1-overview-diagram-2.svg
            ├── 2-architecture/
            │   ├── index.md
            │   └── assets/
            └── 问答-2026-09-10/
                └── index.md
```

- 每个 `.md` 与它自己的 `assets/` 在同一层文件夹里，相对路径固定，整包搬进笔记库
  （Obsidian / Typora / VS Code）都能正常显示架构图
- **重复导出会覆盖更新**：同一页面再导一次，`index.md` 与 `assets/*.svg` 直接被新内容覆盖，
  不会多出 `index (1).md`、`xxx-diagram-1 (1).svg` 这类副本
- 关掉设置里的「一篇一个文件夹」会退回旧的平铺模式：
  `DeepWiki/<仓库>-<页面>.md` + `DeepWiki/<仓库>-<页面>.assets/`
- 文件夹内正文文件名默认 `index`，可在设置里改（比如改成 `{pageId}`、`README`）

## 六、常见问题

**Q：点了下载但没反应？**
- 检查 Chrome 下载设置里是否允许该站点下载多个文件（批量导出会一次下载很多文件）
- 若浏览器拦截了自动下载，地址栏右侧会有提示，选「允许」再重试

**Q：问答页面导出说「未找到问答内容」？**
- 答案还在流式生成中，等它生成完再点一次

**Q：页面刚跳转过来，按钮没出现？**
- DeepWiki 是单页应用，刷新一次页面即可

**Q：导出后架构图在笔记软件里显示不出来？**
- 默认的「独立 .svg 文件」模式需要 `.md` 和同名 `.assets` 文件夹放在一起
- 只想拿一个文件就选「内嵌 base64」（注意：Obsidian 和 GitHub 不渲染 base64 图片，Typora / VS Code 可以）

**Q：译文没被导出？**
- 按顺序排查：
  1. 页面上确实显示着译文吗？（没翻的部分导出必然是英文）
  2. 用陪读蛙的话，它只翻「滚动到过」的部分。导出时若提示覆盖率不足，选「滚动并等待」；
     或者直接跑一遍批量导出——它会逐页滚动补齐
  3. 没有陪读蛙时，用沉浸式翻译并开启「自动翻译」
  4. 面板/弹窗上会显示「译文 N/M 处」；如果是 0，说明插件的译文没进 DOM，
     那就不是本扩展能解决的（可以换「双语对照」模式再试）
- 沉浸式翻译的默认模式（把译文写进页面 DOM）是完整支持的

**Q：导出后排版中英混在一行？**
- 不会。1.1.0 起整段译文会另起一段；行内译文（跟着词组的小片段）才保持内联。

**Q：批量导出很慢 / 有些页面失败？**
- 先看设置里的「批量导出的译文处理」：
  - **只导出原文（默认）**：不滚动、不等翻译，每页只等正文和架构图渲染完，几十页通常几分钟跑完
  - **逐页等待译文**：每页要多滚几轮、等翻译补齐，约 10~15 秒/页，84 页差不多 40 分钟
- 它要在当前标签页里逐页打开，期间尽量别切走这个标签页（切走后渲染会变慢）
- 过程中可以随时点「停止」，已经导出的页面都在
- 结束提示里会给出失败页数，控制台（`[DeepWiki→MD]` 前缀）里能看到具体是哪几页，
  可以单独打开那页再导出
- 如果某页在侧边栏里找不到链接（目录折叠或页面不在目录里），会跳过并计入失败列表

**Q：我要的是英文原文，为什么导出的文件里混了中文？**
- 原文模式会临时关掉陪读蛙的页面翻译再导出；如果你用的是别的翻译插件（或手动翻译过页面），
  导出走的就是「页面上当前的内容」。结束提示里若出现「N 页仍带译文」，就是这种情况，
  把那几页在**关闭翻译后**重新导出即可。

**Q：为什么批量导出要占用我的标签页，不能后台跑？**
- DeepWiki 是单页应用，正文与 Mermaid 架构图都要在真实页面里渲染完才抓得到；
  翻译插件（尤其是陪读蛙）同样只在**顶级页面**里注入，藏起来的 iframe 里根本没有插件。
  所以翻页必须在当前标签页里做。

## 七、目录结构与开发

```
deepwiki-md-exporter/
├── manifest.json
├── icons/                        图标（16/32/48/128）
├── src/
│   ├── lib/                      turndown.js / turndown-plugin-gfm.js（HTML→Markdown）
│   ├── common/extractor.js       核心：页面识别、内容提取、DOM 清洗、Markdown 组装
│   ├── content/                  内容脚本 + 页面内悬浮面板样式
│   ├── background/               Service Worker、offscreen 下载
│   └── popup/                    工具栏弹窗
└── tools/
    ├── make_icons.py             用标准库重新生成图标
    └── test-extractor.cjs        extractor 回归测试（jsdom，仅测试需要）
```

关键实现说明：

- **提取而不是请求**：所有内容都从实时 DOM 读取（先克隆再清洗），因此翻译结果、展开状态、渲染好的 Mermaid 图都在其中
- **DOM 清洗**：剔除按钮/图标/隐藏元素/翻译插件 UI，图表转成 SVG（序列化后内嵌或落地为文件）
- **陪读蛙适配**：识别 `.read-frog-translated-content-wrapper`（双语对照），
  也认「仅译文」模式的原文本地替换（`data-read-frog-translation-only` / `lang="zh"`）；
  保护译文节点不被「隐藏元素」规则误删、剔除它的加载态与报错 UI、
  并让整段译文在 Markdown 里单独成段
- **引用标记**：把 DeepWiki 的行内引用小标签还原成 `文件:行号`，并用右侧源文件卡片里的 GitHub 链接补成可点击链接
- **译文覆盖率**：按「正文块里的中文是否占多数」判定，两种译文形态、各种翻译插件都适用；
  统计时会排除文件名 / 代码标识符 / 「相关源文件」清单，避免把覆盖率算低
- **导出前译文检查**（单页导出）：覆盖率不足时提供「自动滚动整页 + 等译文稳定」再导出
- **翻译插件开关**：靠 read-frog 悬浮按钮上的勾选徽标定位「页面翻译」开关（与界面语言无关）。
  它是个**开关**，读错状态再点一下就会切反（实测会把整页留成英文），所以做成自纠正的：
  按钮或状态读不到时宁可不点；点完必须看到徽标变成目标状态，否则再点一次（最多 3 次）
- **批量导出**：在当前标签页里顺着侧边栏链接做单页应用内跳转（不整页刷新，内容脚本常驻），
  每页等到「正文长度 + Mermaid 图数量」稳定、且没有待渲染的图表源码后提取，
  再复用同一套提取逻辑。**不用隐藏 iframe**，因为 DeepWiki 的图表要在真实页面里渲染、
  翻译插件也只在顶级页面注入
- **原文模式不滚动页面**：翻译插件是按视口懒翻译的，只要不滚动就不会被触发，
  所以原文模式下每页只等渲染、不等翻译；如果开关本来就是开的，还会先临时关掉、
  整趟结束后恢复，避免正文被就地替换成中文而丢掉原文
- **链接编码**：页面名里带括号（如 `2.6-core-engine-(segcore)`）时，
  Markdown 链接目标会把 `(` `)` 编码成 `%28` `%29`，否则链接会被截断
- **下载**：`conflictAction: 'overwrite'`，同名文件覆盖更新
